# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Masume (升目) is a personal study site for beginner Japanese (kana first) and advanced English. It is plain HTML/CSS/JS with **no framework, no build step and no bundler**. It is served as static files (GitHub Pages: `jdamador.github.io/masume`). The UI is bilingual EN/ES.

## Commands

- **Run locally:** `python -m http.server 8000` from the repo root, then open http://localhost:8000. Opening `index.html` directly also works, but the service worker and the test page need http.
- **Tests:** open http://localhost:8000/test.html in a browser. There is no CLI test runner. The page runs unit checks (`js/tests.js`) and then drives the real app in an iframe (`index.html?seed=demo#/home`), typing with the on-screen keyboard. The heading shows `PASS n / n` or `FAIL ...`. To focus on one check, temporarily comment out the other `test(...)` calls in `js/tests.js`.
- **Demo data:** append `?seed=demo` to the URL (see `seedDemo` in `js/app.js`).
- **English sections:** hidden by default (`MS.config.english = false` in `js/config.js`). Use `?english=on` to show them in one browser; the setting is saved in localStorage.
- **Pronunciation audio** (normally regenerated by CI, see below):
  ```
  pip install edge-tts
  node tools/list-audio.js > tools/audio-list.json
  python tools/make_audio.py
  ```

`package.json` lists `firebase`, but the app does not use `node_modules`. `js/shared.js` loads the Firebase SDK from the gstatic CDN with dynamic `import()`.

## Architecture

- **Global namespace, script-tag ordering.** Every file is an IIFE that attaches to `window.MS` (`MS.store`, `MS.kana`, `MS.srs`, `MS.ui`, `MS.practice`, `MS.session`, `MS.english`, `MS.shared`, `MS.topics`, `MS.numbers`, `MS.app`, ...). There are no ES modules, so load order matters. The order is set by the `<script>` tags in `index.html`, and `js/app.js` comes last because it boots the app. `test.html` loads only the logic modules it unit-tests.
- **Adding a file:** add it to `index.html`, to the `FILES` list in `sw.js`, and bump `CACHE` in `sw.js` (`masume-vN`). The service worker uses network-first and falls back to the cache when offline.
- **Router:** hash-based. The `ROUTES` table in `js/app.js` maps `#/path?query` to view functions `(host, query)`. `route()` calls the `cleanup()` of session, english and shared before each render. `/en/*` routes fall back to home when English is off.
- **Views** are built with the `h(tag, attrs, ...children)` DOM helper from `js/ui.js`. All user-facing strings go through `T('English', 'Español')`.
- **Data:** all user state is one JSON blob in localStorage under `masume.v1` (`js/store.js`, which also contains the defaults schema and export/import). Every storage access is wrapped in try/catch, and the app keeps working in memory when storage is blocked. SRS keys use prefixes: `k:<kana>`, `w:<wordId>`, `e:<englishId>`.
- **Layers:** `kana-data.js`, `srs.js` and `practice.js` are pure logic with no DOM, and they are the parts covered by unit tests. `practice.js` builds activities and generates sessions. `session.js` runs them and renders the Practice pages. `keyboard.js` is the single on-screen kana keyboard that all typing activities use.
- **Content** lives in `data/*.js` (`content.js`, `vocab-sets.js`, `english-data.js`, plus `strokes.js`, which comes from KanjiVG and is CC BY-SA). These files are meant to be edited by hand.
- **Shared study room** (`js/shared.js`): syncs the Words list with a partner through Firestore at `rooms/<sha256(room code)>/words`. Only words sync; SRS and progress stay local. Tests inject a fake backend through `MS.sharedBackend`. Setting `MS.firebaseConfig` to `null` in `js/firebase-config.js` turns the room off. The Firebase web keys in that file are public by design.
- **Firestore rules:** `firestore.rules` is deployed with `firebase deploy --only firestore:rules`, using project `masume-8412a` from `.firebaserc`. The same rules are also embedded as the `RULES` string in `js/shared.js`, which the Study room page displays. If you change one, change the other to match.

## Pronunciation audio pipeline

`Speech` in `js/ui.js` plays a recording from `audio/<id>.mp3` when `audio/manifest.js` (`MS.audio`: text → id) has an entry. Otherwise it uses the browser's TTS. `tools/list-audio.js` loads the data files in a Node `vm` and collects every Japanese string the app can speak. `tools/make_audio.py` records the missing ones with edge-tts, deletes files that are no longer listed, and rewrites the manifest.

- `.github/workflows/audio.yml` runs this on pushes to `main` that touch `data/content.js`, `js/kana-data.js`, `js/session.js`, `js/ui.js` or `tools/**`, then commits the result as `github-actions[bot]`. Pull before pushing again after such a change.
- The `SPEAK_FIX` map in `js/ui.js` is parsed by regex in `list-audio.js` (`const SPEAK_FIX = {...}`). Keep it a flat object literal on that form. `SAMPLE_WORDS` in `js/session.js` is extracted the same way.
- If you add Japanese content in a new data file, add that file to the list in `tools/list-audio.js` and to the workflow's `paths`.
- Do not hand-edit `audio/` or `tools/audio-list.json`.
